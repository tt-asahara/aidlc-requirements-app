# 実モックの画像付き修正指示

API接続画面で、登録済みモックから撮影した実PNGと、ピン／矩形指定をモデルへ渡す機能です。未接続デモの固定画像機能とは別です。

## 利用手順

1. 実行対象のラウンドと rough/refined、画面・議論対象を選びます。過去ラウンドは閲覧専用です。
2. モックを操作し、「画像で修正箇所を指定」→「操作後の状態を撮影」を押します。初期HTMLを撮る場合は幅・高さを選んで「現在のHTMLを撮影」を使います。撮影はモデルを呼びません。
3. 画像上をクリックしてピン、ドラッグして矩形を指定します。Enterによる中央ピン、Escapeによる解除にも対応します。
4. 「指定画像と参照情報を下書きに添付」を押します。サーバーが指定を焼き込んだPNGを生成します。下書きの画像・成果物・ラウンド・hash・viewport・位置と、全文表示される本文を確認・編集します。
5. 「送信」を押すと、表示したPNGの実バイトと本文を既存のCLIへ送ります。クリック・撮影・添付だけではモデルを呼びません。既存本文がある場合は、新しい参照情報に続けて本文を保持するので、古い参照が残っていないか確認してください。
6. 実行終了後に契約を再読込し、現在の版を再撮影して確認します。同じ画像指定ペインを開いている間は前回の撮影も比較できます。比較は自動承認や変更箇所の自動保証ではありません。

画像の添付を解除しても本文は残します。本文に残った画像参照は送信前に確認してください。成果物／ラウンド／版／質問cursorが変わった場合、古い画像の送信を拒否して下書きを保持します。自動再送はしません。

## このMVPの撮影範囲

「操作後の状態を撮影」は、同じsandbox iframe内の読取専用bridgeから現在のDOM・フォーム値・スクロール位置を受け取り、**JavaScriptを無効にして隔離再描画**します。操作中ブラウザーの画素を直接撮る機能ではありません。親はiframeのDOMにアクセスせず、送信元window・一回限りの要求ID・channelを照合します。返却DOMは未信頼データとして扱います。原本hashを照合し、DOM hashを画像の出典として別記録します。外部HTTP等は再描画でも遮断します。

DOMは80KB・5000要素、viewportは下記上限です。canvas・動画／音声・入れ子フレーム・custom element／公開Shadow DOM・password/file入力は明示的に拒否します。閉じたShadow DOMやブラウザー固有のhover/focus状態など、HTMLに投影できない状態の画素一致は保証しません。独自CSPがbridgeを拒否する場合もCSPを緩めず、初期HTML撮影へ戻ります。表示したPNGに意図した状態が写っているか確認してください。

「現在のHTMLを撮影」は従来どおりスクリプト無効の初期描画です。業務状態の選択は議論対象であり、自動再生はしません。未接続デモは固定初期画像を使い、操作後撮影・モデル送信は実行しない旨を明示します。

撮影時は独立ブラウザー、空のsandbox iframe、offline context、service worker/WebSocket禁止を使用します。読み取り済みの同じ契約ディレクトリの静的資源だけを仮想originへメモリ配信します。外部HTTP、file URL、script、form、子frame、ローカルファイルの読取を許可しません。ブラウザーにはAWS認証環境を渡しません。通常の操作用iframeは従来の `sandbox="allow-scripts"` のままで、allow-same-originを付けません。

上限はPNG2MiB、viewport幅320–1600／高さ240–1200、DPR1、資源64件・計8MiB・列挙128件・深さ4です。画像はワークスペース外のprivate app data内、owner/projectごとに短期保存し、20分期限・同時撮影1件・project内16画像を上限とします。画像アップロードや任意URLを入力するAPIはありません。

## 送信と既存工程

`POST /turns` は画像の参照IDを制御メタデータとして受け取り、所有者、期限、PNGの型・サイズ・hash、実行context、契約・資源hashをadmission前とCLI直前に再検証します。画像はstream-jsonのbase64 image block、本文は表示された全文をtext blockとしてstdinへ渡します。画像用の隠れたプロンプトは追加しません。通常のテキスト送信は従来のargv経路を維持します。

CLI入力receiptには画像のhash・サイズ・寸法と本文hashを記録します。base64画像を重複してログへ書きません。CLI未起動のstale/取消は既存zeroCall経路を使い、以前の累計・未精算予約を消しません。

画像は参照資料であり、permission APIや正式な工程承認を代替しません。原本を変更するには既存の正規rework、review、gateが必要です。HTML変更だけで要件や統合文書が変わったとは扱いません。「要件・文書への反映を相談」では、変更内容・範囲、標準候補の要件／正式AC／モック契約／操作仕様／統合索引の現在hashまたは未生成状態を表示し、変更案を求める編集可能な下書きを作ります。実資料との個別章対応は不明と表示し、推測しません。関連資料の版もadmission前・CLI直前に検証します。変更案を確認後、既存の「要件を開き直す」→正式対話・レビュー・ゲート→「設計書を更新」を利用者が明示実行する導線です。承認済み原本への無条件の自動全同期は行いません。外部エディタとの完全な原子性や画像の永続版管理も保証しません。

## 検証

- `bun run lint && bun run typecheck && bun test && bun run build`
- `bun run e2e`（専用fakeサーバー・独立データ）
- `scripts/check-visual-capture.ts`：合成HTMLの外部HTTP/file/script試行、同じディレクトリのCSS、symlink除外、画像指定、CSS途中更新の拒否を実ブラウザーで確認します。モデルを呼びません。
- `runner.test.ts`：記録用CLIで、watchdogを通したstdinの実PNGと本文の一致、receipt、画像ログ省略を確認します。
- `visual.test.ts`：owner、別project、期限、入力上限、資源更新、admission/pre-CLI、zeroCallを確認します。

限定した実Bedrock検証では、未承認の独立合成予約画面を用い、本文にもHTML/CSS文字列にもない画像内コードをReadツールより前に読めること、CSS色指定1箇所だけが変わること、再撮影の画素差分がその境界線だけになることを確認しました。fixtureの準備はoperatorが行い、編集はモデルが実施しました。これは画像入力と局所編集のE2Eであり、正式AI-DLC工程の完走・本人の主観的承認・ドキュメント統合の再検証ではありません。

## 表示と次の操作

幅1101px以上では「中央を広く表示」と左右それぞれの開閉を使えます。下書きとiframeは表示切替時に保持し、画像／反映案の下書きを作ると会話を開きます。狭幅と200%拡大では既存の領域タブを使います。成果物一覧は画面原本、要件・正式AC、全ラウンド統合設計書を分けます。HTML/CSS補助・内部ログを主一覧へ混在させません。許可待ちは次操作を表示しますが、許可後も送信は自動で行いません。
