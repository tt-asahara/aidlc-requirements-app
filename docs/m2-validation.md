# M2: ターン実行とキュー（モデル不使用）

## 到達点

`TurnRunner`（CLI / 録画再生）、stream-json パーサー、SQLite `Store`、明示送信型の `TurnManager` を実装した。
`createRuntime` が設定に従って runner を選び、起動時に中断ターンを失敗にする。起動・復旧自体からモデルを呼ばない。
画面は PR #3 の未接続デモを維持している。プロジェクト API と SSE の HTTP 配信は M4、画面接続は M5。

## 実行・停止の境界

- プロンプトは保存した文字列を一つの argv に置き、全オプションの後に `--` を入れる。シェルを通さない。
- `--setting-sources project,local` を常に指定し、`AIDLC_UNATTENDED` を渡さない。
- 子の HOME は `<data>/claude-homes/<project>`。既存 AWS 設定ファイルは元のパスを参照するだけで、認証情報をコピーしない。
- Bun の内部プロセスホストは `--no-env-file --no-install` で起動する。ワークスペースの `.env` から環境が再混入しない。
- `Bun.spawn(detached: true)` のプロセス群へ SIGTERM、10 秒後に残っていれば SIGKILL。CLI が先に終了しても残った子孫を停止する。
- 非公開の内部 IPC ホストがサーバーとの切断を検知する。サーバー強制終了後も同じ停止処理を行う。新しいサービス抽象化は追加しない。
- CLI を開始する前にプロセス群の PID 記録をアプリログ側へ保存する。再起動時は旧群が消えるまで待ち、12 秒後も残る・記録が壊れている場合は復旧を拒否する。他プロセスへ推測で kill を送らない。
- データディレクトリは PID と固有トークンのロックで一つのサーバーだけが所有する。不明なロックを強制削除しない。

CLI の最大予算は厳密な請求停止ではない。M1 実測・計画修正 PR #4 と同様、超過する可能性がある。
追加の Bedrock 実行は行っていない。M1 の請求照合待ちは維持している。

## 永続化と費用

手書き SQL migration を transaction で適用する。`users`、`projects`、`turns`、`permission_requests` を作り、FK / WAL を有効にする。
queued と running の部分ユニークインデックスにより同じプロジェクトの二重送信を 409 相当で拒否する。別プロジェクトは並行可能。

同じ Claude セッションの累計の差分をターン費用にする。CLI init を確認した時点で session_started を更新し、失敗した初回も以後は resume する。
結果なし・減少した累計などは費用未確定として予約を残す。後続の同じセッションの累計で照合できた場合、未知分を含む差分と照合フラグを保存する。
既知費用と未確定予約を合算して admission を判定し、残りがなければ 402 相当、CLI に渡す上限は残枠とターン上限の小さい方。
別セッションの予約を解放しない。セッション不在の 0 ターン / 0 費用は既存累計を巻き戻さない。

復旧で queued は未実行費用 0、running は費用未確定として failed にする。自動再送しない。
イベントは DB に保存せず購読者へ渡す。DB には最終結果、入力文字列、費用、時刻を保存する。

## 許可とログ

拒否の証跡を project ごとに pending として重複排除して保存する。この段階には承認・拒否・取消 API がなく、自動許可も自動続行もない。
ワイルドカードや改行を含む Bash コマンドなど、完全一致ルールとして安全に表現できると未確認の入力は `rule=""` の証跡にとどめる。
空ルールやワイルドカードを追加の allowedTools に渡さない。M7 では CLI の正確なルール構文を検証し、許可不能なカードの扱いを確定する必要がある。
基本許可リストは毎回ワークスペースから読む。上流の不足をアプリ側で補わない。

stdout は JSON をパースして文字列・秘密フィールドを伏せ、stderr は行ごとに伏せてからファイルへ書く。
同じ伏せ字済みデータだけをイベント・結果・許可証跡へ渡し、別の raw ログを残さない。既知の環境秘密値、改行を含む値の断片、AWS / GitHub / API キーの既知パターンを対象にする。
任意の未知の秘密値を完全検出できる保証はない。ログの公開・ダウンロード API はまだない。DB とログはリポジトリ外、DB / ログファイルは 0600。

## Linux main CI の終了待ち修正

PR #5 の push / PR CI は成功したが、マージ後の main CI `39391370401` で、タイムアウト試験の SIGKILL 直後に子 PID が一時的に残る競合を検出した。
SIGKILL の配送と孤児プロセスの回収は非同期なので、送信成功だけで停止完了とせず、プロセス群の消滅を最大 1 秒待つ。
消滅しない場合は失敗として残し、プロセス PID 記録を削除しない。テストの停止検証を緩めず、実装側の完了条件を修正した。
