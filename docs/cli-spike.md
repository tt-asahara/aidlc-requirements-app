## 実行条件

- Bedrock、`ap-northeast-1`、`jp.anthropic.claude-sonnet-4-6`。既存の既定 AWS 認証を使用し、STS とモデル利用認可を読み取り確認してから開始。

### 確定した CLI の扱い

- オプションの後に `--` を置き、その後のプロンプトを一つの argv 要素として渡せる。ハイフン始まりも成功。stdin は空のままでよい。
- `total_cost_usd` と `modelUsage.*.costUSD` は resume をまたぐセッション累計。`usage` は呼び出し単位であり、両者を混同しない。
- 費用の基準は session ごとに保持する。再接続後の新 UUID は基準 0。ターンにも使った session ID を保存し、過去の別 session の値を差し引かない。
- 予算超過は `error_max_budget_usd`。`result` 本文がなく `errors` 配列だけでも正常な失敗結果である。
- 存在しない session は `error_during_execution` かつ `errors` / stderr に `No conversation found with session ID:`。任意の `error_during_execution` を session 消失とみなさない。
- `error_max_turns` は予算超過ではなく通常の失敗。今回 `--max-turns 6` に対して result の `num_turns` は 7 だったため、その値を API 呼び出し数や厳密な課金上限として扱わない。
- 最初の AI-DLC 呼び出しが失敗でも、その session は保存され resume できた。`claude_session_started` を「最初の成功」だけで立てると同じ UUID の新規開始を繰り返すため、開始イベントの記録で立てる。
- `Bun.spawn({detached:true})` は Bun 1.3.14 の型定義に存在する。Mac で子と孫が同じ独立 PGID に属し、負の PGID への SIGTERM で両方消えることをモデルなしで確認した。6.2 の node spawn 指定を Bun に統一できる。

M1 の各実行に追加許可の拒否はなかった。上流の既知ハッシュ / evidence 許可不足を直したわけではなく、rough-mockups はまだ実行していない。

## 合計予算と予約の根拠

**M8追記（2026-10-20）:** 以下はM1当時の暫定記録。公式FoundationModels東京単価と実modelUsageの照合により700USD仮予約を精算し、保守的計上1.11USD・残998.89USDへ更新した。請求確定とは区別する。根拠と現在の実E2Eブロックは [operations.md](operations.md) を参照。

今回の M1 と将来の M8 を合わせた利用者承認は **1,000 USD 以下**。使い切る目標ではない。
外部データディレクトリの `verification/budget.json` を正本とし、各呼び出しの前に仮枠を確保した。新規の資格情報は台帳に含めない。

- **推定費用 0.75214965 USD** は Claude Code が返した list-price estimate。AWS の請求確定額ではない。
- **予約 700 USD = 7 回 × 100 USD** は暫定的に大きく取った仮枠で、実費でも、AWS が保証する最大値でもない。価格・終了時の計上方式を確認する前に、同時実行せず多くの余裕を残すために採用した。
- `--max-budget-usd 0.00001` でも `0.04738905` が返ったことを実測した。CLI 上限は事前の厳密な料金遮断ではないため、完了したという理由だけでは仮枠を解放しなかった。
- 累計と差分の方式は今回確認できたが、推定が AWS の東京向け適用料金と完全一致することは確認していない。公開 AmazonBedrock price-list の東京データにはこの Anthropic モデルの行を見つけられず、一般的なモデル紹介記事の料金だけで個別請求を確定しない。
- 照合は、同じ model / provider / region の適用料金（入出力、cache write / read、TTL）と取得済みのトークン使用量で行う。必要なら遅延する AWS 請求明細と照合するが、同じアカウントの他利用を本タスクの費用に混ぜない。追加アクセスや権限が必要なら勝手に取得・拡張しない。
- 照合済みの範囲と根拠を台帳に記録してから予約を解除・精算する。現時点では未精算予約を維持し、追加課金は正確な残枠を判断できるまで停止する。承認上限そのものは変更しない。
- M2 以降のモデル不要実装・テストは、この仮枠が大きいことを理由に止めない。

CLI の見積もり、上限超過の可能性、resume 時の個別 cap については [公式 CLI reference](https://code.claude.com/docs/en/cli-reference) と実測を参照。モデルの地域料金は [AWS の料金ページ](https://aws.amazon.com/bedrock/pricing/) で確認する。

## M2 前に明示する計画修正

| 変更 | 根拠 |
|---|---|
| Bun の detached に統一 | 5.2 と 6.2 の矛盾を、型定義と実プロセスグループ確認で解消 |
| プロンプト前の `--` を採用 | ハイフン入力と resume を実測済み |
| CLI 用 HOME をプロジェクト単位で隔離し、AWS の既存ファイルはパスだけで参照可能にする | 他の業務資料・個人設定を検証入力へ持ち込まず、資格情報をコピーしないため |
| 生ログ保存から、保存前の秘密値・既知パターンの伏せ字へ変更 | I7 と「そのまま保存」の矛盾。SSE・結果・stderr にも同じ処理を適用 |
| session の開始判定とターンの session ID 保存 | 最初の失敗後の resume と再接続後の費用差分を正しく扱うため |
| 再起動では queued も失敗へ | 待ち行列を復元・自動送信せず、古い queued が永久に 409 を起こさないようにする |
| 費用未取得のターンを 0 とみなさず予約を残す | 結果欠落で無料と推定しない。次の同一 session の累計で精算する場合は、その差分が未取得分も含むことを記録 |
| 既定のデータディレクトリをリポジトリ外へ変更 | I8 と `./data` の矛盾を解消。M1 の明示エラーから、M2 で安全な既定へ移行 |

元の計画は初回保存コミットに保持されている。変更はこの文書 PR で示し、M2 のコードはそのマージ後に実装する。
