# Local inventory and bounded content reads

Local browsing must not depend on the total bytes or file count of a publishable shared snapshot. The metadata inventory reads no file bodies, returns at most 200 items per page, visits at most 800 directory entries per request, bounds traversal depth and cached pages, and exposes incomplete/cancelled/changed enumeration explicitly. Symlinks, hardlinks, hidden/private paths remain excluded with visible exclusion counts. Files above the content budget remain listable.

Content selection uses a separate bounded safe reader with actual-byte hash and private-content validation (2MiB per file, including growth after stat). Preview and annotation bind the selected HTML, resources actually served inside its isolated directory, associated contract bytes/presence and active-space/intent pointers. Unrelated project files do not define the scene version. New or changed resources invalidate a captured proof. Each scene retains metadata only, with 128 resources / 16MiB total, four concurrent reads and at most 32 pending requests. Shared publication continues using the unchanged complete-manifest validation (20MiB total, 2MiB per file, 2000 files, lease/version fencing and server validation).

The UI shows partial/cancelled/dirty enumeration and localized content errors. Refresh starts a new inventory; cached previous pages are limited to eight. File events mark the projection dirty and refresh known control files/selected resources, rather than repeatedly reading the entire project. Explicit mockup selection still verifies contract asset bytes, whereas background projection clearly reports integrity as unchecked. Metadata revisions are not content hashes. Cancellation closes directory handles and fences results from an old project/cursor.

Verification uses `inventory.nodecheck.mjs`, `preview-scene.nodecheck.mjs`, the default-versus-metadata server reader regression, and `scripts/v3/large-inventory-ui.mjs` (also `--packaged`). The synthetic 2105-file / 137,953,280-byte history fixture must cause zero history body reads while paging; tests additionally cover native HTML/CSS/PNG capture, contract and resource changes, cancellation, root replacement, private contents and links. Machine-readable results live outside the checkout in the task evidence directory. The user's running app and project files are not updated or moved.
